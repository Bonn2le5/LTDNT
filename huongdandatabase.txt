13.1. TEST Ở TẦNG DATABASE (SSMS)
--------------------------------------------------------------------------------
Mở 2 query window riêng biệt trong SSMS.

Window 1 - chạy:
  USE DatSanTheThao;
  GO
  BEGIN TRAN;

  INSERT INTO dbo.DatSanChiTiet
      (DatSanId, SanId, ChiNhanhId, NgaySuDung,
       ThoiGianBatDauUtc, ThoiGianKetThucUtc, ThuTuSlot, GiaSlot, TrangThai)
  VALUES
      (NEWID(), 1, 1, '2026-01-15',
       '2026-01-15T11:00:00Z', '2026-01-15T11:30:00Z', 1, 50000, 'BOOKED');

  -- GIỮ TRANSACTION MỞ (chưa COMMIT)

Window 2 - chạy:
  USE DatSanTheThao;
  GO
  BEGIN TRAN;

  INSERT INTO dbo.DatSanChiTiet
      (DatSanId, SanId, ChiNhanhId, NgaySuDung,
       ThoiGianBatDauUtc, ThoiGianKetThucUtc, ThuTuSlot, GiaSlot, TrangThai)
  VALUES
      (NEWID(), 1, 1, '2026-01-15',
       '2026-01-15T11:00:00Z', '2026-01-15T11:30:00Z', 1, 50000, 'BOOKED');

Kết quả kỳ vọng ở Window 2:
  Msg 2601, Level 14, State 1, Line X
  Cannot insert duplicate key row in object 'dbo.DatSanChiTiet' with
  unique index 'UX_DSCT_San_Slot_DangChiem'.
  The duplicate key value is (1, 2026-01-15 11:00:00.000).
  The statement has been terminated.

=> Đây chính là bằng chứng hệ thống chống Double Booking ở tầng DB.

Dọn dẹp:
  Ở Window 1: ROLLBACK TRANSACTION;

13.2. TEST 100 REQUEST ĐỒNG THỜI BẰNG POWERSHELL
--------------------------------------------------------------------------------
Tạo file test-concurrency.ps1:

  $ErrorActionPreference = "Continue"
  $baseUrl = "https://localhost:7174"
  $token = "YOUR_JWT_TOKEN_HERE"

  $body = @{
      sanId = 1
      thoiGianBatDau = "2026-01-15T11:00:00Z"
      thoiGianKetThuc = "2026-01-15T11:30:00Z"
  } | ConvertTo-Json

  $headers = @{
      "Authorization" = "Bearer $token"
      "Content-Type"  = "application/json"
  }

  $jobs = 1..100 | ForEach-Object {
      Start-Job -ScriptBlock {
          param($url, $body, $headers)
          try {
              Invoke-RestMethod -Uri "$url/api/dat-san/khoa-tam" `
                  -Method Post -Body $body -Headers $headers -SkipCertificateCheck
              return "SUCCESS"
          } catch {
              return "FAILURE"
          }
      } -ArgumentList $baseUrl, $body, $headers
  }

  $results = $jobs | Wait-Job | Receive-Job
  $jobs | Remove-Job

  $successCount = ($results | Where-Object { $_ -eq "SUCCESS" }).Count
  $failureCount = ($results | Where-Object { $_ -eq "FAILURE" }).Count

  Write-Host "SUCCESS: $successCount" -ForegroundColor Green
  Write-Host "FAILURE: $failureCount" -ForegroundColor Red

  if ($successCount -eq 1) {
      Write-Host "PASS - Chỉ 1 request thành công" -ForegroundColor Green
  } else {
      Write-Host "FAIL - Có $successCount request thành công (kỳ vọng = 1)" -ForegroundColor Red
  }

Chạy: .\test-concurrency.ps1

Kết quả kỳ vọng:

  Could not execute because the specified command or file was not found.

Khắc phục:
  dotnet tool install --global dotnet-ef --version 10.*
  Đóng và mở lại Terminal
  dotnet ef --version

14.3. LỖI KẾT NỐI SQL SERVER
--------------------------------------------------------------------------------
Triệu chứng:
  Microsoft.Data.SqlClient.SqlException: A network-related or instance-specific
  error occurred while establishing a connection to SQL Server.

Khắc phục:
Bước 1 - Kiểm tra SQL Server đang chạy:
  Windows: Get-Service MSSQLSERVER
  Docker : docker ps | grep sqlserver

Bước 2 - Kiểm tra port 1433:
  Windows: Test-NetConnection localhost -Port 1433
  Linux  : nc -zv localhost 1433

Bước 3 - Bật TCP/IP (SQL Server local):
  - SQL Server Configuration Manager
  - SQL Server Network Configuration
  - Protocols for MSSQLSERVER
  - Chuột phải TCP/IP - Enable
  - Restart SQL Server service

Bước 4 - Kiểm tra firewall (mở port 1433).

14.4. LỖI LOGIN FAILED FOR USER 'SA'
--------------------------------------------------------------------------------
Nguyên nhân: SA bị disabled hoặc sai password.

Khắc phục:
Bật SA login (chạy trong SSMS với Windows Authentication):
  ALTER LOGIN sa ENABLE;
  GO
  ALTER LOGIN sa WITH PASSWORD = N'A7!dX9zQ';
  GO

Đảm bảo SQL Server ở Mixed Mode:
  - Chuột phải SQL Server - Properties
  - Security - chọn SQL Server and Windows Authentication mode
  - Restart SQL Server service

14.5. LỖI CANNOT OPEN DATABASE "DATSANTHETHAO"
--------------------------------------------------------------------------------
Nguyên nhân: Database chưa được tạo.

Khắc phục:
  cd backend/SportBooking.Api
  dotnet ef database update

Hoặc tạo database thủ công:
  CREATE DATABASE DatSanTheThao;
  GO
Sau đó chạy lại dotnet ef database update.

14.6. LỖI CANNOT INSERT DUPLICATE KEY KHI CHẠY MIGRATION
--------------------------------------------------------------------------------
Nguyên nhân: Database đã có bảng cũ hoặc migration chạy 2 lần.

Khắc phục:
  sqlcmd -S localhost,1433 -U sa -P "A7!dX9zQ" -d DatSanTheThao ^
         -Q "SELECT * FROM __EFMigrationsHistory"

  sqlcmd -S localhost,1433 -U sa -P "A7!dX9zQ" ^
         -Q "ALTER DATABASE DatSanTheThao SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE DatSanTheThao"

  dotnet ef database update

14.7. LỖI CERTIFICATE CHAIN NOT TRUSTED
--------------------------------------------------------------------------------
Khắc phục:
Option 1: Thêm TrustServerCertificate=True vào connection string.
Option 2: dotnet dev-certs https --trust

14.8. LỖI PORT 1433 ALREADY IN USE
--------------------------------------------------------------------------------
Khắc phục:
Kiểm tra process chiếm port:
  Windows: netstat -ano | findstr :1433
  Linux  : lsof -i :1433

Đổi port mapping (Docker):
  docker run -d ^
    --name sqlserver-sportbooking ^
    -e "ACCEPT_EULA=Y" ^
    -e "MSSQL_SA_PASSWORD=A7!dX9zQ" ^
    -p 1434:1433 ^
    mcr.microsoft.com/mssql/server:2022-latest

Sửa connection string: Server=localhost,1434;...

14.9. LỖI SYSTEM.GLOBALIZATION.CULTURENOTFOUNDEXCEPTION
--------------------------------------------------------------------------------
Khắc phục: Thêm vào đầu file Program.cs:
  using System.Globalization;
  CultureInfo.DefaultThreadCurrentCulture = new CultureInfo("en-US");
  CultureInfo.DefaultThreadCurrentUICulture = new CultureInfo("en-US");

14.10. LỖI EF TOOLS CŨ HƠN RUNTIME
--------------------------------------------------------------------------------
Khắc phục:
  dotnet tool update --global dotnet-ef

14.11. LỖI DOCKER DAEMON NOT RUNNING
--------------------------------------------------------------------------------
Khắc phục:
  - Mở Docker Desktop
  - Đợi icon Docker chuyển sang xanh (running)
  - Chạy lại lệnh docker

14.12. LỖI CANNOT ACCESS A DISPOSED CONTEXT INSTANCE
--------------------------------------------------------------------------------
Nguyên nhân: DbContext bị dispose trong khi có async operation.

Khắc phục: Kiểm tra code - đảm bảo không dùng using var db = new AppDbContext()
với async, mà inject qua DI.

14.13. LỖI KHI CHẠY DOCKER TRÊN WINDOWS
--------------------------------------------------------------------------------
Triệu chứng:
  error during connect: This error may indicate that the docker daemon is not running.

Khắc phục:
  - Mở Docker Desktop
  - Đợi Docker running
  - Chạy lại lệnh docker

PHẦN 15 - FAQ (CÂU HỎI THƯỜNG GẶP)
================================================================================

Q1: Tôi dùng macOS, có chạy được SQL Server local không?
A: SQL Server không chạy native trên macOS. Phải dùng Docker (Cách B)
   hoặc Azure SQL (Cách C).

Q2: Repo có bao gồm database sẵn không?
A: Không. Database được tạo từ EF Core Migration hoặc script SQL.
   Không commit file .mdf / .bak lên Git vì lý do bảo mật và dung lượng.

Q3: Password sa bị lộ trong appsettings.json có sao không?
A: Đây là password mẫu cho môi trường dev. BẮT BUỘC đổi khi deploy production
   và KHÔNG commit password thật lên Git. Dùng User Secrets hoặc Environment
   Variables.

Q4: Tôi muốn reset database về trạng thái ban đầu?
A: sqlcmd -S localhost,1433 -U sa -P "A7!dX9zQ" ^
          -Q "ALTER DATABASE DatSanTheThao SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE DatSanTheThao"
   cd backend/SportBooking.Api
   dotnet ef database update

Q5: Làm sao chạy trên CI/CD (GitHub Actions)?
A: Thêm vào .github/workflows/ci.yml:
   - name: Start SQL Server
     run: |
       docker run -d --name sqlserver \
         -e "ACCEPT_EULA=Y" \
         -e "MSSQL_SA_PASSWORD=A7!dX9zQ" \
         -p 1433:1433 \
         mcr.microsoft.com/mssql/server:2022-latest

   - name: Run migrations
     run: dotnet ef database update
     working-directory: backend/SportBooking.Api

Q6: Làm sao backup database?
A: BACKUP DATABASE DatSanTheThao
   TO DISK = 'C:\Backups\DatSanTheThao.bak'
   WITH FORMAT, INIT, COMPRESSION, STATS = 10;

Q7: Database chiếm bao nhiêu dung lượng?
A: Database rỗng ~50 MB. Sau khi seed + vài nghìn booking ~200 MB.

Q8: Có cần Redis không?
A: Không bắt buộc cho dev. Production nên thêm Redis để cache availability
   và rate limiting.

Q9: Làm sao thêm migration mới khi thay đổi entity?
A: cd backend/SportBooking.Api
   dotnet ef migrations add TenMigrationMoi
   dotnet ef database update

Q10: Làm sao rollback migration?
A: dotnet ef database update TenMigrationTruoc   # Rollback về migration cụ thể
   dotnet ef database update 0                    # Rollback toàn bộ

Q11: Tôi không có SQL Server, có thể dùng gì khác?
A: Có thể dùng:
   - SQL Server Express (miễn phí, giới hạn 10GB)
   - SQL Server Developer Edition (miễn phí cho dev)
   - Azure SQL Database (đám mây, có free tier)
   - Docker SQL Server (khuyến nghị)

Q12: Làm sao biết database đã sẵn sàng cho đồ án?
A: Chạy PHẦN 16 - CHECKLIST, tất cả mục phải được tick.
